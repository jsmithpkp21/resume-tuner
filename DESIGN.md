# 📘 Résumé Builder — System Design Specification

> **Status:** Draft — under review (see GitHub issues)
> **Created:** 2026-03-25
> **Repo:** [jsmithpkp21/resume-builder](https://github.com/jsmithpkp21/resume-builder)

This document defines the complete architecture, rules, constraints, and behaviour
of the résumé builder system. It is designed to be deterministic, audit-friendly,
space-bounded, relevance-driven, and layout-aware.

---

## Stack

| Concern | Approach |
|---|---|
| Data — skills | Skills Matrix CSV (single source of truth) |
| Data — experience | YAML files (one per job) |
| Routing rules | Plain-text, AI-interpreted |
| Relevance scoring | Python relevance engine |
| Layout enforcement | Python layout engine |
| Role summaries | AI summary generator |
| Document assembly | Python template engine |
| Output | PDF and DOCX via Python libraries |
| AI interface | Python wrapper (OpenAI-compatible) |
| Dependency on Notion | **None** |

---

## 1. Skills Matrix CSV (Source of Truth)

Six columns — all fields quoted (`"..."`), empty fields `""`:

| Column | Purpose |
|---|---|
| `Skill` | Skill name (may be shortened in output as last resort) |
| `Category` | Grouping label |
| `General Definition` | What the skill means generally |
| `My Application` | How I have used it |
| `Routing Rule` | Fallback override (see below) |
| `Design Notes` | Free-form notes |

### Routing Rule values (fallback only)

```
always | only_if_required | legacy | learning | niche | avoid_by_default
```

The résumé builder relies primarily on General Routing Rules (§3). This field
is a last-resort override. The CSV is **never modified** by the builder; any
skill renaming happens only in the output layer.

---

## 2. Experience Database (YAML)

One YAML file per job. Schema:

```yaml
job_title: "Senior Software Engineer"
company: "Example Corp"
start_date: "2018-01"
end_date: "2022-06"

general_role_description: |
  High-level description of what the role actually involved.
  Raw material for the summary generator.

bullets:
  - text: "Designed deterministic automation frameworks for multi-device labs."
    skills: ["Automation", "Framework Design", "Python"]
    categories: ["Automation & Framework Engineering"]
    impact: "high"
    domain: "testing"

  - text: "Stabilised CI pipelines by addressing environment drift."
    skills: ["CI/CD", "Debugging"]
    categories: ["CI/CD & Tooling"]
    impact: "medium"
    domain: "infrastructure"
```

### Rules
- Minimum **3 bullets** per experience entry
- The **first line under each job** is a 1–2 line role summary generated by AI
  (not a bullet) — built from `general_role_description` + selected bullets +
  target job description
- Ensures clarity, relevance, consistency, and no redundancy with bullets

---

## 3. General Routing Rules (AI-interpreted)

These rules govern skill, category, bullet, and experience selection.
The AI must follow them when building the résumé.

### Skill & Category Selection
1. Select skills relevant to the job description, title, and company domain
2. Prioritise skills used within the last **15 years**
3. Drop or de-prioritise older skills unless explicitly relevant
4. Limit categories to **6–7**
5. Limit skills section to a **fixed line budget** (see §5)
6. Merge categories when needed to fit space constraints
7. Drop skills in this order: unrelated → old → implied → niche → legacy → low-impact
8. Avoid single-word line wraps by adjusting category grouping, skill ordering,
   skill renaming (last resort), or dropping low-relevance skills

### Experience Selection
9. Include only experiences with end date within **15 years**
10. Order by **relevance + recency**
11. Each experience must include **at least 3 bullets**
12. First line under each job = 1–2 line summary, not a bullet
13. Summaries must reflect the role, selected bullets, and target job description

### Document-Level Rules
14. Résumé must fit within **two pages** (±1–2 lines tolerance)
15. Most relevant information must appear highest
16. Skills not tied to a specific job may appear in an **Additional Skills** section
17. Avoid empty space and overcrowding
18. Avoid single-word or two-word line wraps anywhere

---

## 4. Relevance Engine

Scores skills, categories, bullets, and experiences against:

- Job description keywords
- Job title
- Company domain / industry
- Seniority level
- Recency
- Frequency of use
- Impact level (`high` / `medium` / `low`)

Outputs: selected categories, skills, bullets, experiences, and ordering for
each section.

---

## 5. Layout Engine (Space & Line Budget)

### Skills Section
- Max lines: **10–12**
- Max categories: **6–7**
- Max characters per line: template-dependent

### Layout Enforcement (in order)
1. Fit skills into line budget
2. Merge categories if needed
3. Drop low-relevance skills
4. Reorder skills to avoid widows/orphans
5. Rename (shorten) skills — **last resort only**
6. Reflow until no single-word wraps remain

### Experience Section
- Each job: 1–2 line summary + 3–6 bullets (space-dependent)
- Bullets must not wrap awkwardly
- Bullets must be concise and high-impact

### Document Layout
Two-page hard limit. If over limit (in order):
1. Drop low-relevance bullets
2. Shorten summaries
3. Drop low-relevance skills
4. Merge categories
5. Compress spacing

---

## 6. Category Merging Rules

Merging is output-only — never modifies the CSV.

Examples:
- "Automation & Framework Architecture" + "Automation & Framework Engineering"
  → "Automation & Frameworks"
- "Debugging & Analysis" + "Distributed Systems & Infrastructure"
  → "Systems & Debugging" (if space requires)

---

## 7. Skill Renaming Rules (Last Resort)

Only when a skill causes line-wrapping issues in output:

| Original | Shortened |
|---|---|
| "Scalable UI/API automation" | "Scalable automation" |
| "Distributed tracing" | "Tracing" |
| "AI-assisted architecture exploration" | "AI architecture" |

Rules: never change meaning; never modify the CSV; only modify output.

---

## 8. Summary Generation

The 1–2 line role summary under each job must:
- Reflect the actual role
- Incorporate the selected bullets
- Align with the target job description
- Avoid redundancy with bullets
- Avoid single-word wraps
- Fit within 1–2 lines

Example pattern:
> "Led deterministic automation and CI stability efforts across multi-device and
> hybrid cloud environments, improving reliability and reducing flakiness through
> layered framework design and distributed debugging."

---

## 9. Output Formats

- **PDF** — primary output; enforces page limits and typography
- **DOCX** — secondary output; matches PDF structure

Template engine handles: spacing, line lengths, page breaks, font consistency,
section ordering, widow/orphan prevention.

---

## 10. End-to-End Workflow

```
skills.csv         → validated by pytest
experience_db/     → bullet tagging
job_description    → relevance scoring
                          │
                    relevance engine
                    selects & orders:
                    categories, skills,
                    bullets, experiences
                          │
                    layout engine
                    enforces line budget,
                    merges/drops/renames
                          │
                    summary generator
                    1–2 line role summaries
                          │
                    template engine
                    assembles document
                          │
                    output generator
                    PDF + DOCX
```

---

## 11. Guiding Principles

1. **Relevance over completeness**
2. **Space-bounded, not count-bounded**
3. **Layout-aware, not text-dumping**
4. **AI-driven, rule-guided**
5. **Deterministic and reproducible**
6. **No single-word wraps**
7. **Two pages maximum**
8. **Minimal manual intervention**
9. **CSV remains the canonical source**
10. **Output may rename or merge — source never changes**
