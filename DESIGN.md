# 📘 Résumé Builder — System Design Specification

This document defines the complete architecture, rules, constraints, and behavior of the résumé builder system. It is designed to be deterministic, audit‑friendly, space‑bounded, relevance‑driven, and layout‑aware.

The system uses:
- A canonical **Skills Matrix CSV** (single source of truth)
- A structured **Experience Database**
- A set of **General Routing Rules**
- A **Relevance Engine**
- A **Layout Engine**
- A **Template Engine**
- AI‑driven reasoning for selection, summarization, and formatting

The goal is to produce a clean, professional résumé that:
- fits within **two pages** (±1–2 lines)
- avoids **single‑word line wraps**
- dynamically selects **skills, categories, and experiences**
- adapts to the **job description, job title, and company**
- outputs to **PDF and Word**
- requires minimal manual intervention

---

# 1. Skills Matrix (Source of Truth)

The Skills Matrix CSV contains six columns:

1. **Skill**
2. **Category**
3. **General Definition**
4. **My Application**
5. **Routing Rule** (rarely used; last‑resort override)
6. **Design Notes**

### Rules
- All fields must be quoted (`"..."`)
- Empty fields must be `""`
- Skill names may be **renamed/shortened** by the résumé builder *as a last resort*
- The CSV is **never modified** by the résumé builder; renaming is done only in the output layer

### Routing Rule (rarely used)
Allowed values:
```
always
only_if_required
legacy
learning
niche
avoid_by_default
```

This field is a **fallback override**.
The résumé builder should rely primarily on **General Routing Rules** (Section 3).

---

# 2. Experience Database

Each experience entry contains:

- **Job Title**
- **Company**
- **Start Date**
- **End Date**
- **General Role Description** (raw description of what the role actually was)
- **Bullet Bank** (tagged with skills, categories, impact types, domains)

### Rules
- The résumé builder must select **at least 3 bullets** per experience
- The **first line under each job** is **not a bullet**
- Instead, it is a **1–2 line role summary** generated by AI using:
  - the general role description
  - the selected bullets
  - the job description for the target role

This ensures:
- clarity
- relevance
- consistency
- no redundancy with bullets

---

# 3. General Routing Rules (AI‑interpreted)

These rules replace the need for most Routing Rule values.

AI must follow these rules when selecting skills, categories, bullets, and experiences.

### Skill & Category Selection
1. Select skills relevant to the job description, job title, and company domain.
2. Prioritize skills used within the last **15 years**.
3. Drop or de‑prioritize older skills unless explicitly relevant.
4. Limit the number of categories to **6–7**.
5. Limit the total skills section to a **fixed line budget** (see Layout Rules).
6. Merge categories when needed to fit space constraints.
7. Drop skills in this order:
   - unrelated
   - old
   - implied
   - niche
   - legacy
   - low‑impact
8. Avoid single‑word line wraps by adjusting:
   - category grouping
   - skill ordering
   - skill renaming (last resort)
   - dropping low‑relevance skills

### Experience Selection
9. Include only experiences with an end date within **15 years**.
10. Order experiences by **relevance + recency**.
11. Each experience must include **at least 3 bullets**.
12. The first line under each job is a **1–2 line summary**, not a bullet.
13. Summaries must reflect:
    - the role
    - the selected bullets
    - the target job description

### Document‑Level Rules
14. The résumé must fit within **two pages**, with a tolerance of ±1–2 lines.
15. The most relevant information must appear highest in the résumé.
16. Skills not tied to a specific job may appear in an **Additional Skills** section.
17. Avoid empty space and avoid overcrowding.
18. Avoid single‑word or two‑word line wraps anywhere in the document.

# 4. Relevance Engine

The relevance engine scores:

- skills
- categories
- bullets
- experiences

Based on:

- job description keywords
- job title
- company domain
- industry
- seniority
- recency
- frequency of use
- impact level

The engine outputs:

- selected categories
- selected skills
- selected bullets
- selected experiences
- ordering for each section

---

# 5. Layout Engine (Space & Line Budget)

The layout engine ensures the résumé fits within the required space and avoids awkward wrapping.

### Skills Section Line Budget
- Max lines: **10–12**
- Max categories: **6–7**
- Max characters per line: template‑dependent

### Layout Enforcement
The engine must:

1. Fit skills into the line budget.
2. Merge categories if needed.
3. Drop low‑relevance skills.
4. Reorder skills to avoid widows/orphans.
5. Rename skills (shorten) as a **last resort**.
6. Reflow text until no single‑word wraps remain.

### Experience Section Layout
- Each job gets:
  - 1–2 line summary
  - 3–6 bullets (depending on space)
- Bullets must not wrap awkwardly.
- Bullets must be concise and high‑impact.

### Document Layout
- Total document must fit within **two pages**.
- If over limit:
  - drop low‑relevance bullets
  - shorten summaries
  - drop low‑relevance skills
  - merge categories
  - compress spacing

---

# 6. Category Merging Rules

Categories may be merged dynamically to fit space constraints.

Examples:

- “Automation & Framework Architecture”
  + “Automation & Framework Engineering”
  → “Automation & Frameworks”

- “AI‑Assisted Quality”
  + “AI‑Assisted Quality Engineering”
  → “AI‑Assisted Quality Engineering”

- “Debugging & Analysis”
  + “Distributed Systems & Infrastructure”
  → “Systems & Debugging” (if needed)

Merging is allowed only in the **output**, not in the CSV.

---

# 7. Skill Renaming Rules (Last Resort)

If a skill causes line wrapping issues, the résumé builder may shorten it.

Examples:

- “Scalable UI/API automation” → “Scalable automation”
- “Distributed tracing” → “Tracing”
- “AI‑assisted architecture exploration” → “AI architecture”
- “Automation troubleshooting” → “Troubleshooting”

Rules:
- Only shorten when necessary
- Never change meaning
- Never modify the CSV
- Only modify the output

---

# 8. Summary Generation Rules

The 1–2 line summary under each job must:

- reflect the actual role
- incorporate the selected bullets
- align with the target job description
- avoid redundancy
- avoid single‑word wraps
- fit within 1–2 lines

Example pattern:
> “Led deterministic automation and CI stability efforts across multi‑device and hybrid cloud environments, improving reliability and reducing flakiness through layered framework design and distributed debugging.”

---

# 9. Output Formats

The résumé builder must support:

- **PDF**
- **Word (DOCX)**

The template engine handles:

- spacing
- line lengths
- page breaks
- font consistency
- section ordering
- widow/orphan prevention

---

# 10. End‑to‑End Workflow

```
skills.csv  →  pytest validation
experience_db → bullet tagging
job description → relevance scoring

→ relevance engine selects:
    - categories
    - skills
    - bullets
    - experiences

→ layout engine:
    - enforces line budget
    - merges categories
    - drops low‑relevance items
    - avoids single‑word wraps
    - shortens skills if needed

→ summary generator:
    - creates 1–2 line role summaries

→ template engine:
    - assembles résumé
    - formats sections
    - enforces 2‑page limit

→ output generator:
    - PDF
    - DOCX
```

---

# 11. Guiding Principles

1. **Relevance over completeness**
2. **Space‑bounded, not count‑bounded**
3. **Layout‑aware, not text‑dumping**
4. **AI‑driven, rule‑guided**
5. **Deterministic and reproducible**
6. **No single‑word wraps**
7. **Two pages maximum**
8. **Minimal manual intervention**
9. **CSV remains the canonical source**
10. **Output may rename or merge as needed**
